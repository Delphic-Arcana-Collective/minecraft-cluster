# 注意点

- 在 Kubernetes 上跑一批 Minecraft 服务器。
- 镜像只用 itzg 的。
- 集群怎么调度，自己设计。
- 自己的模组列表怎么装进去，还要单独弄清楚。
- 一个集群里要有多台服。
- 这一阶段每台服用不同的 NodePort，前面不挂 Minecraft 代理。
- 同一个端口分到不同后端，以后再在自己的网关里用插件做。
- 那只能靠 Minecraft 自己的协议来认，因为 TCP/IP 里没有地方写主机名。

## 思考通路

先定下镜像。统一只用 itzg。

集群调度由我们自己设计。

现阶段每台服各占一个 NodePort，前面不挂 Minecraft 代理。

同一个端口分流到不同后端的事留到以后。由于只能依赖 Minecraft 自身的协议，到时会在我们自己的网关里靠插件实现。

自定义 mods 的装法已经查明。列表不烘进镜像，容器启动时写进 /data，具体落进 mods 还是 plugins 目录取决于 TYPE。

采用 StatefulSet 编排并为每个 Pod 挂载独立的持久卷。当前这台服务端为 Forge 1.20.1，容器镜像选用 Java 21，通过 Helm 部署到 192.168.1.114 的 k3s 集群，并以 NodePort 作为外部访问入口。
